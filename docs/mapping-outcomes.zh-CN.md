# 映射结果与原因分类

[English](mapping-outcomes.md) · [README](../README.zh-CN.md) · [参考文档](reference.zh-CN.md) · [原理说明](how-it-works.zh-CN.md)

本文整理当前已知的未映射、歧义和执行异常。结果代码描述映射停在哪一步，具体原因解释为什么停在这里；两者并非一一对应。同一个 `no_match` 可能来自身份不同，也可能因为正确商品没有进入候选列表。

下面包含已复核的商品现象，以及实现和测试覆盖的边界情况，不代表每种边界都在生产中发生过。商品样本核实日期为 **2026-10-31**，后续销售状态和接口返回可能变化。

## 映射结果

成功时目标返回 `nsuid`，否则返回 `code` 和 `reason`。程序应按稳定的 `code` 分支，`reason` 用于说明，措辞可能调整。

| `code`                  | 类别                         | 已知原因或触发条件                                                                                                                                                     |
| ----------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `source_not_found`      | 源商品未读取到               | 源 NSUID 不属于指定地区的目录，商品已不可读取，或上游没有返回该条目。不能直接认定商品不存在。                                                                          |
| `unsupported`           | 当前类型不支持               | 独立消耗品、目录兑换券、订阅票券本身、未知类型，或组合包含有当前无法建立跨区身份的成员。普通时间券的有限支持不包含订阅票券本身，也不包含组合包中的票券成员。           |
| `insufficient_identity` | 身份资料不足或矛盾           | 缺少 application ID、平台、ROM rights 或完整成员；无法推导有效所属本体；Demo 关系不完整；时间券身份缺失或矛盾。具体情况见下文。                                        |
| `unresolved`            | 跨区入口未解析到商品         | Redirector 不返回目标区具体商品，或源 application ID 在目标区无法解析。相同作品可能在不同地区使用不同 application ID。DLC 和组合包也可能因所属本体无法解析而停在这里。 |
| `no_candidates`         | 没有发现目标候选             | 本体已解析，但关联列表没有所需类型；商品已下架或从列表隐藏；目标本体没有同平台 Demo；目标票券组缺失或普通时间券列表为空。                                              |
| `no_match`              | 有候选，但没有身份相同的商品 | 平台、完整 ROM rights、组合包成员或成员数量不同；消耗品成员商业键不同；时间券组、发行商、精确分钟数或订阅关联不同。正确商品未进入列表时也可能得到此结果。              |
| `ambiguous`             | 无法确定唯一商品             | 多个目标商品身份相同，或源商品、所属本体和关系链本身存在歧义。见[歧义原因](#歧义原因)。                                                                                |
| `incomplete`            | 候选查找未完成               | 达到所属本体或分页上限，或上游声明还有结果却提前返回空页。DLC／组合包相关查找最多读取 16 个所属本体，每个本体最多 40 页、每页 100 条；未完成的查找不能确认唯一性。     |

这些结果都不能单独证明目标区没有销售该商品。下架、目录差异、候选发现限制和身份差异可能产生相同结果。

### 身份资料不足的细分情况

| 类型       | 具体情况                                                                                                                                                                                                    |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Title／DLC | 缺少 application ID、平台或完整 ROM rights；DLC 内容编号格式异常，或不在可推导所属本体的有效范围内。                                                                                                        |
| Bundle     | 缺少平台、ROM rights、成员列表或有效本体锚点；本体／DLC 成员缺少平台、application ID 或 rights；消耗品成员缺少有效 `itemId` 或发行商 ID。                                                                   |
| Demo       | 缺平台或所属本体；源本体没有列出这个 Demo、只列出其他 Demo，或同平台 Demo 列表为空。单向关联不足以确认对应关系。                                                                                            |
| 普通时间券 | 缺少有效组 ID、发行商、精确正整数分钟数或明确的订阅关联；声明的组 ID 与嵌套组不一致；源组未列出该票券身份；组内普通时间券资料不完整，或同一 NSUID 出现相互矛盾的身份数据。缺失订阅字段不等同于明确的 null。 |

身份缺失发生的位置会影响结果代码。目标 Title／DLC／Bundle 的候选缺少身份时，可能因没有匹配成功的候选而表现为 `no_match`；不能仅凭代码断定是字段缺失还是商品不同。普通时间券会显式阻止使用身份不完整的候选组。

## 歧义原因

NSUID 标识销售商品；application ID、ROM rights 和组合包成员主要描述软件权益。多个销售条目可以具有相同的软件权益。`ambiguous` 表示现有证据无法选择唯一 NSUID，可以是合理的多对应关系。

| 原因类别                     | 已知现象与例子                                                                                                                                                                             | 处理原则                                                                   |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 同款有多个销售条目           | 旧版与再发行版并存、发行商变更。AVICII Invector: Encore Edition 的 JP `70070000021578` 对应的 HK 候选包括旧条目 `70070000011231` 和新条目 `70070000021580`；公开内容身份相同，发行商不同。 | 完整保留候选。发行商变更本身不否定同款关系，不据此自动排除旧条目或新条目。 |
| 商业版本不同，但公开身份相同 | Let's Sing 2024 的普通、Gold、Platinum 版本公开 rights 和成员相同；Dreamlight 普通与 Magical DLC 共用权益编号。                                                                            | 保留歧义。需要额外商业版本证据，不能只按名称、发售日期或销售状态选一个。   |
| 同一权益被多个商品条目共用   | 多个 DLC 章节或分批内容共享同一套 rights；同一组多张时间券具有相同分钟数和订阅关联。                                                                                                       | 同权益不足以证明销售商品一一对应。普通时间券要求源区和目标区均能唯一识别。 |
| 关系链本身不唯一             | 源／目标本体有多个同平台 Demo；Demo 所属本体映射有歧义；多个所属本体指向不同 Demo；源区同组时间券身份重复。                                                                                | 说明歧义发生的位置，不把本体或源区 NSUID 混入目标商品候选。                |

这些类别是解释原因的分类，并非新增 API 代码，也不是互斥的统计桶。同一组条目可能同时存在再发行和商业版本差异；不能仅凭 `ambiguous` 自动归类。

当前 Title／DLC／Bundle 整体候选不会按商品发行商排除。组合包中消耗品成员的发行商 ID 用于限定 `itemId` 的作用域；普通时间券的有限支持也要求组发行商相同。这两处身份校验与上述再发行条目的发行商差异应分别理解。

### 候选字段

- 目标区同类型的多个商品匹配成功时，返回 `ambiguous` 和排序、去重后的 `candidates`，不返回唯一 `nsuid`。
- 源区同组时间券身份重复时，在请求目标区前停止，`source` 和目标均带 `ambiguous`；不返回目标 `candidates`。
- 源本体有多个 Demo，或 Demo 的父本体映射有歧义时，不把这些源 Demo／父本体编号放进目标 Demo 的 `candidates`，相关信息由 `reason` 说明。

### 已复核的例子

| 源商品与目标                                             | 观察                                                                                                                                               |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Let's Sing 2024，GB `70070000018040` → HK                | 六个候选的公开内容指纹相同。发行商只能把候选分成两组，每组仍有普通、Gold、Platinum 三个条目；独立时间券的支持无法补出组合包与具体 VIP 票券的关系。 |
| Dreamlight: The Storybook Vale，GB `70050000052283` → JP | 普通版 `70050000052289` 与 Magical Edition `70050000052286` 共享 `0100d39012c1b003`，仍为两个候选。                                                |
| Let's Sing VIP，HK `70080000002057`                      | 源组有三张相同 43200 分钟、无订阅关联的普通时间券，在请求目标区前保持歧义。                                                                        |

Dreamlight 的组合包正向成员关系可以提供复核线索，但必须先独立确认源和目标组合包的商业版本对应。不能用相同的冲突 rights 映射组合包，再反过来证明其中的 DLC 对应；DLC 的反向组合包列表有漏项，空列表也不能作为排除证据。这些线索尚未接入自动映射规则。

## 输入与执行异常

这些情况会抛出异常，与正常返回的映射结果分开记录。

| 异常                           | 类别           | 典型原因                                                                                                                           |
| ------------------------------ | -------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `TypeError`                    | 输入或配置无效 | NSUID、application ID、地区代码格式错误；目标为空或超过 8 个；超时、重试、SKU 枚举等参数超出允许范围。具体校验取决于所调用的方法。 |
| `NsuidMapError.kind = network` | 网络失败       | 连接或 TLS 失败、响应正文读取失败等。                                                                                              |
| `timeout`                      | 请求超时       | 单次请求及其重试耗尽时间预算。                                                                                                     |
| `abort`                        | 调用取消       | 调用方取消，或整次调用的 `signal` 达到时间限制。                                                                                   |
| `http`                         | HTTP 错误      | 限流、服务端错误或其他被适配器视为异常的状态码。Redirector 的 200／404 被解释为未解析到商品，不会直接作为 HTTP 异常抛出。          |
| `graphql`                      | GraphQL 错误   | 权限拒绝、字段或参数不被接受、认证配置不符，或上游返回其他 GraphQL 错误。HTTP 200 也可能带有这些错误；部分 `data` 不会掩盖错误。   |
| `response`                     | 响应格式异常   | 非 JSON、GraphQL 外层结构异常、缺少有效 `data`。                                                                                   |
| `other`                        | 其他协议异常   | 例如 redirector 返回重定向状态却没有 `Location`。                                                                                  |

网络错误、HTTP 429／5xx 会在允许的重试次数和单次请求预算内重试，并遵守 `Retry-After`。权限或查询字段错误通常需要处理权限、配置或查询本身。`timeout` 和 `abort` 会终止当前请求，不会通过内部重试重新开始一份时间预算。

任一目标执行异常会使整个 `mapNsuid` 调用抛出；不会自动转换成该目标的业务结果代码。需要保留其他目标结果时，使用[底层函数](reference.zh-CN.md#底层函数)分别处理。

## 目录资料与快照问题

- 目录缺名或名称为 `?`：只是资料缺口；mapper 不比较名称，缺名本身不触发 `ambiguous`，也不能作为排除候选的依据。
- 名称本地化、标点或版本命名不同：不能直接证明商品相同或不同。
- 导出快照未刷新：记录的是过去一次检查；不能视为当前任天堂目录或当前线上映射状态。
- 只选 `PUBLIC` 的组合包成员快照：可能漏掉 `UNSEARCHABLE` 成员，不能用于证明完整内容相同。Mapper 当前比较成员时同时选择这两种状态。

记录复核结论时，保留原始 `code`、`reason`、已有候选以及检查时间，另行说明已确认的原因和证据。未确认的原因保持未知，不把缺名、下架或某个返回代码自动解释为“目标区没有销售”。
