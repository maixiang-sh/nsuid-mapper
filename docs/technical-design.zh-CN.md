# NSUID Mapper 技术设计

## 职责与结构

这是独立的跨区商品编号映射库，只依赖 JavaScript / Web API，不依赖其他 Savanna 客户端。它不保存商品资料、不提供 HTTP 服务，也不内置数据库或缓存。

- `src/client.ts`：公开方法、参数校验和目标国家并发调度。
- `src/mapping.ts`：本体、DLC、合集的匹配决策。
- `src/upstreams/savanna.ts`：必要的 GraphQL 查询、身份标准化和关联项分页。
- `src/upstreams/redirector.ts`：Nintendo Apps Redirector 请求和跳转解析。
- `src/retry.ts`：两个上游共用的重试次数校验、指数退避和可取消等待；不增加公开导出。

输入一个 NSUID、源国家和最多 8 个目标国家，返回源身份和每个目标国家的 `nsuid` 或未映射 `reason`。不比较名称、发行商名称或文案相似度。

```ts
const result = await mapper.mapNsuid('70070000039411', {
  from: 'US',
  to: ['JP', 'GB'],
});
```

NSUID 是地区商品编号；Application ID 是内容锚点，但不能单独保证两个商品是同一版本。本体与 Switch 2 Edition 可以共用 AppID，多权益 DLC 也不能只靠第一个权益描述全部内容。

## 本体与 DLC

**本体**：从源商品读取 AppID、`labelPlatform` 和全部 `romRights.titleId`，先检查证据是否齐全；缺失时直接返回原因，不发起目标国家请求。Redirector 返回的商品只是入口，继续读取它及 `upgradeInfo` 关联的基础版 / 升级版身份。只有 AppID、平台、完整权益集合都一致且仅有一个候选时才返回映射。

**DLC**：读取平台与全部 `romRights.titleId`，对所有权益推导父应用编号并去重。解析目标父商品，分页读取其 DLC 列表及首页的 `upgradeInfo.upgradeDlcItem`，比较平台与完整权益集合。相同 NSUID 在两条路径重复出现时只算一个候选；不同 NSUID 都匹配时返回歧义原因。权益顺序、大小写和重复 ID 不影响比较。扫描未完成时，不接受此前找到的候选。

DLC 也限制最多 16 个父应用候选，通常所有权益只指向同一个父应用。缺少平台 / 权益、权益不是有效应用编号或没有目标父商品时返回未映射原因。

`resolveNsuidsToAppIds` 使用更小的独立查询，只返回编号，不读取合集成员。该方法的单个 ID 返回值也不表示完整商品身份。

## 合集：完整身份与唯一候选

### 1. 源身份

读取合集自身的：

- `labelPlatform`
- 全部 `romRights.titleId`
- `itemsV2(publicStatuses: [PUBLIC, UNSEARCHABLE])`

每个成员至少读取 `__typename`。支持的成员进一步读取：

| 成员类型           | 身份字段                                                          |
| ------------------ | ----------------------------------------------------------------- |
| `ApplicationItem`  | `labelPlatform`、全部 `applications.id`、全部 `romRights.titleId` |
| `DlcItem`          | `labelPlatform`、全部 `romRights.titleId`                         |
| `ConsumableItemV2` | `itemId`、`consumableItemGroup.publisher.id`                      |

应用 / 权益 ID 去空白、转小写、去重并排序。应用和 DLC 成员形成包含“类型、平台、应用 ID 集合、权益集合”的规范签名；消耗品成员形成包含“类型、发行商 ID、itemId”的签名。全部成员签名排序后比较，保留重复成员的数量。地区 NSUID、名称和成员排列顺序不参与身份比较。

`itemId` 是不透明字符串，保留原值和大小写，不去空白或解析其中的单词；空白字符串视为缺失。发行商 ID 必须是正的安全整数。合集的父应用、平台和完整权益也必须匹配，不单独依赖 `itemId` 的全局唯一性。`consumableItemGroup.id` 不参与比较：NBA 2K26 的分组 ID 随地区变化，但对应成员的 `itemId` 和发行商 ID 相同。源身份和候选身份共用这组最小字段查询，不读取消耗品文案、价格或分组详情。

`contentAppIds` 是全部成员应用 / 权益编号的并集，仅用于发现父应用；`contentKeys` 是用于比较的成员签名列表。两者都是本库生成的元数据，不是上游字段。

### 2. 候选发现

1. 从所有成员 ID 推导父应用 ID，去重后逐个通过 Redirector 获取目标父商品。
2. 分页读取目标父商品的 Bundle 关联编号，首页同时读取 `includedBundleItems`。DLC 条目只保留类型名用于计算分页偏移，不读取其平台和权益。
3. 沿 `upgradeInfo` 中的基础版和升级版链接继续读取父商品，避免只找到基础版的合集。
4. 合集编号去重，分批读取完整候选身份。
5. 扫描完所有可达父商品，比较合集平台、完整权益和成员签名。仅一个匹配才返回结果；多个匹配返回歧义原因。

成员与关联项均包含 `UNSEARCHABLE`，避免漏掉地区之间公开状态不同、但实际携带订阅时长或附加权益的商品。销售状态筛选使用已确认合法的 `ONSALE`、`PRE_ORDER`、`SALES_TERMINATION`、`UNRELEASED`。

### 3. 无法可靠匹配的情况

- 合集没有平台、权益或成员。
- 成员缺少平台 / 权益，或本体成员缺少应用 ID。
- 消耗品成员缺少有效的 `itemId` / 发行商 ID，或成员类型尚不支持。
- 完整匹配的候选不止一个。
- 父商品扫描或分页触及上限。
- 空页返回时，已扫描数量仍小于上游声明的 `total`。
- 上游关联列表未暴露目标商品，例如已确认的 `NOT_SALE` 合集。

以上返回未映射原因，不忽略缺失成员、不选第一个匹配，也不回退到普通版本。消耗品分组 ID 在地区间可能不同，不能当通用跨区外键；名称同样不能作为兜底。

## 请求成本和边界

- 最多 8 个目标国家并发；同一个国家的父商品串行扫描。
- 每个国家最多扫描 16 个父商品；关联项每页 100 条，每个父商品最多 40 页。
- 每次最多读取 50 个合集完整身份，防止一次返回过大的嵌套列表。
- 一个普通合集通常需要源身份请求 1 次、每个国家 3 次；关联版本、多个父应用、分页或多个身份批次会增加请求数。
- 达到上限且扫描未完成时，不接受此前找到的 DLC 或合集候选。若最后一页刚好完成扫描，不视为截断。
- 提前空页停止请求，标记扫描未完成，并给出区别于分页上限的原因；`total: 0` 的空页正常完成。此异常通过真实身份字段构造响应验证，本次线上正常分页未出现。
- `upgradeInfo` 仅在每个父商品首页选择；DLC 模式读取升级包身份，合集模式读取关联父商品编号。完整合集身份仍统一查询，不删减用于准确匹配的字段。
- Demo / Consumable 独立商品没有本库用于发现目标父商品的应用编号，返回原因。消耗品 `itemId` 可用于合集内成员匹配，但没有按 `itemId` 查询其他地区商品的入口。
- 身份查询在 `itemsV2` 公共层选择 `__typename`、`nsUid`。已存在但不支持映射的兑换券 / 课程券返回 `kind: 'unknown'` 和包含实际类型名的原因，不再误报商品未找到。未由 `itemsV2` 返回的订阅券仍无法识别。
- 上游请求失败通过 `NsuidMapError` 抛出；业务上的未映射通过 `reason` 返回。单个国家出现硬错误仍会使本次调用拒绝，没有改为部分成功协议。
- Savanna 和 Redirector 默认单次请求总超时 10 秒，最多额外重试 2 次。`retries` 同时控制两个上游，支持构造默认值与单次调用覆盖，`0` 禁用，上限为 `5`。网络错误、429 / 5xx 采用指数退避和抖动；调用方取消可打断等待。
- Savanna 的 429 / 5xx 即使带 GraphQL `errors` 也按 HTTP 暂时失败处理。其他 GraphQL 错误、其他 4xx、异常成功响应、超时和调用方取消不重试。Redirector 的 200 / 404、没有商品的跳转不重试，缺少 Location 的跳转直接报错；只使用响应头，主动释放响应体。
- HTTP 200 的 JSON 外层及 `data` 必须为对象，`errors` 若存在必须为对象数组。异常返回 `NsuidMapError(kind: 'response')`，不会抛普通空对象访问错误；此处不进行完整商品 schema 校验。
- 单次 `timeoutMs` 同时覆盖 Savanna 和 Redirector；两个上游的重试及退避都共享各自请求的预算。多步映射的总时长可能更长，调用方可传入 `AbortSignal` 控制整个操作。

若调用方自行缓存映射结果，升级这次匹配规则后应清除旧 DLC / 合集结果或变更缓存版本，避免继续使用此前的错误映射。本库没有缓存可自动清除。

```bash
bun run check           # 构建、类型、格式、lint 和离线测试
bun run test:live       # 真实接口测试
LIVE=1 bun test tests/  # 全部测试，包括线上验证
```

线上测试只对网络 / 超时等暂时故障重试一次；断言和 schema 错误不重试，第二次失败仍报错。应在修改查询或匹配规则后执行线上测试，并核实因上游数据变化造成的断言失败。
